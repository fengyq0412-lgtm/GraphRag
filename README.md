# GraphRAG Lite

一个可以本地运行的、以证据为中心的 GraphRAG 原型。默认使用 **SQLite + FTS5**：实体和关系作为表存储，断言保留指向原文块的精确引文；查询时结合文本检索和多跳图遍历，以 RRF 融合、轻量重排后生成带引用的回答。SQLite 官方支持 [FTS5](https://www.sqlite.org/fts5.html) 和[递归图查询](https://www.sqlite.org/lang_with.html#queries_against_a_graph)，适合单机原型与中小规模数据。需要多人并发写入、复杂 Cypher 或图原生运维能力时，可换 Neo4j 数据适配层。

## 启动

需要 Python 3.11+，无需安装服务或 Python 第三方库。

```bash
python -m graphrag_lite.cli seed
python -m graphrag_lite.cli serve --port 8000
```

打开 <http://127.0.0.1:8000>。可试问：`星图项目的测试负责人属于哪个团队？请给出关系路径。`

页面中的**知识图谱**可搜索实体或关系，点击节点查看关联断言，点击连线查看原文证据并跳转来源文档；支持拖动节点与滚轮缩放。**已入库文档**提供标题/正文搜索、分页、完整正文、分块以及该文档抽取的关系，也显示待审核文档并标明它暂不进入图谱。回答里的证据也能直接打开对应文档。

样例包含 12 份文档：组织、系统组件、知识处理、检索、发布依赖、质量闭环和评测等关系。其中“待审核变更示例”故意与现有负责人断言冲突，运行 `seed` 后可在**冲突审核**体验处理流程。待审核版本不会进入检索或图谱。

CLI 查询与评测：

```bash
python -m graphrag_lite.cli ask "星图项目的测试负责人是谁？"
python -m graphrag_lite.cli eval
```

可以通过 `--db path/to/file.sqlite` 或 `GRAPHRAG_DB` 更换数据库路径。

## 文档导入与模型

导入 JSON：`python -m graphrag_lite.cli ingest document.json`。文件包含 `title`、`text`，以及可选的 `facts`。每条 fact 至少有 `subject`、`predicate`、`object`、`quote`；可加 `subject_type`、`object_type`、`confidence`。`quote` 必须是对应文本块内的连续原文，否则拒绝该断言。详见 `evals/corpus.json`。

未传 `facts` 时，关系抽取调用 OpenAI 兼容 Chat Completions API。复制项目根目录的配置示例，并填写实际模型信息：

```bash
cp .env.example .env
```

在 `.env` 中填写 `LLM_API_KEY` 和 `LLM_MODEL`；使用其他兼容服务时修改 `LLM_BASE_URL`。启动命令和页面新增文档都会读取该文件，无需再执行 `export`。`.env` 已被 Git 忽略，不要把真实密钥写入 `.env.example`。若同时设置了系统环境变量，以系统环境变量为准。`GRAPHRAG_DB` 也可写入 `.env`。模型响应较慢时可设置 `LLM_TIMEOUT=180`（默认 180 秒，允许 5–600 秒）。若服务支持 `enable_thinking` 参数，可设置 `LLM_ENABLE_THINKING=false` 缩短简单关系抽取的等待时间；不支持该参数的服务请留空。

配置模型后，回答会尝试用证据生成自然语言；未配置时返回带引用的原文摘录。模型输出的引用 ID 会校验是否属于本次检索证据，校验失败则退回原文摘录。模型抽取结果同样经过 quote 定位校验。不要将它当作强事实蕴含验证：**引文存在不代表回答必然被引文支持**。

## 流程与接口

`POST /api/ingest` 接受 `{"title":"...","text":"...","facts":[...]}`；省略 facts 时自动抽取。`POST /api/ask` 接受 `{"question":"...","mode":"auto","max_hops":3}`。`GET /api/graph?q=...` 返回可视化实体、断言及证据（最多 150 条断言）；`GET /api/documents?q=...&limit=25&offset=0` 返回文档列表，`GET /api/documents/{id}` 返回全文、分块和断言。`GET /api/resolutions` 查看疑似重复实体，`POST /api/resolve` 传 `{"id":"...","action":"merge|distinct"}`。`GET /api/stats` 返回统计。

### 新增、版本更新与冲突

- **新增**：页面“新增文档”或 `POST /api/ingest` 创建 v1。相同标题和正文重复提交会返回已有记录，不重复写入。
- **更新**：在文档详情打开当前版本，点击“以此版本编辑”；提交新正文、完整的新断言列表和变更说明。接口为 `POST /api/series/{series_id}/versions`，请求体包含 `base_version`、`title`、`text`、`facts`、`note`。版本历史保留每一版的正文和断言，可查看快照及与上一版的文本/关系差异。新版本替代同系列的旧版本；检索只使用当前生效版本。
- **并发编辑冲突**：提交时以 `base_version` 做乐观锁校验。若当前版本已变化，返回 HTTP 409 和 `current_version`；编辑者需重新打开最新版，手工合并后再提交。不会悄悄覆盖较新的内容。
- **断言冲突**：新旧生效文档出现相同主体、相同谓词、不同客体时，新版本转为 `pending`，暂不参与图谱或回答。`GET /api/conflicts` 查看冲突及双方证据，`POST /api/conflicts/resolve` 提交 `series_id`、`version`、`action`。`replace` 采用新版并令冲突的旧断言退出检索；`coexist` 并列保留双方且标记为争议，问答显示冲突提醒；`reject` 驳回新版，当前版本继续生效。历史快照均保留。
- **抽取方向校验**：针对“X 的某关系是 Y”这类明确句式，入库时以引文统一关系方向和标签，并统一实体类型大小写；即使模型抽取成反向英文关系，也会触发同一关系的冲突审核。
- **文本一致性**：`replace` 后旧断言所在文档可能仍有其他有效关系。检索时只屏蔽旧断言对应的原文摘录，保留其他有效内容；历史文档仍显示完整原文，并提示哪些关系已被替换。若新旧断言共用同一段不可分割的摘录，整块文本退出检索，避免旧事实进入回答。
- **边界**：当前冲突候选规则是“同一实体 + 谓词，不同客体”，会把合法的一对多关系也送审。审核人可选“并列保留”。系统不自动判断哪条事实真实，也不自动合并过期编辑。

可用 `GET /api/series/{series_id}/versions` 查看版本列表，`GET /api/series/{series_id}/diff?from=1&to=2` 查看版本差异。

1. **抽取与入库**：文本分块；每条断言验证精确摘录、置信度和实体类型；文档、块、实体、别名、断言分别持久化。
2. **消歧**：同类型精确别名自动匹配；模糊相似项进入人工队列，避免误合并。页面可合并或保留。
3. **路由**：依据问题中出现的实体与多跳词选择文本、图谱或融合路径；页面显示理由，可手动改写。
4. **检索**：文本使用 FTS5 英文词匹配和中英文词项覆盖；图谱从命中实体双向遍历 1–3 跳。两个排序以 `1/(60+rank)` 做 RRF。
5. **重排与回答**：本地重排综合问题词覆盖、RRF 与图谱支持；回答绑定本次证据块 ID，前端显示来源、路径和打分。

## 评测

`evals/questions.json` 包含单跳、多跳、三跳、系统架构、发布依赖、纯文本和不可回答等 8 个样例。`eval` 输出：

- 路由准确率：选中的路径与标注一致。
- `source_recall_at_6`：期望文档进入前六证据的比例。
- 多跳覆盖：结果中是否出现标注的最小跳数。
- 引用合法率：引用 ID 是否属于本次返回的证据。
- 拒答准确率：无证据问题是否拒答。

真实数据上线前应扩充评测集，按单跳/多跳、同名实体、冲突事实、否定句、时效性和证据不足分层；人工盲评**答案正确性、每句是否被引文支持、路径是否忠实于断言**。当前自动评测不包含独立的事实蕴含判定，也未测试大规模性能。

## 当前边界

这是单机 MVP。文本检索未使用向量嵌入；本地重排是可解释规则，并非 cross-encoder；文本块较大时跨块 quote 会被拒绝。`serve` 默认只绑定 `127.0.0.1`，没有身份认证，不宜直接暴露到公网。
